Generations

A generation is an immutable rule set. Cleaning never changes what readers see until approval.

Prepare a new rule generation

Runs a separate backfill over historical events. Incremental arrivals join it while it builds.

Processes

Queue, workers and the query service are separate processes on one database.

“Stop worker (exit)” kills the process mid-run. Arrivals keep landing in the queue; start it again and the pending work items are cleaned from where the queue left them.

How a query is assembled

  1. raw event (immutable, every revision kept)
  2. serving window by event time → one generation
  3. published result for that generation + revision

All three read from one snapshot, so a switch returns the old set or the new set — never a splice.
